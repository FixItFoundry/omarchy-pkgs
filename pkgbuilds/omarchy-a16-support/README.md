# ASUS Zenbook A16 support files

This package contains the public audio topology, matching UCM, WirePlumber keep-awake policy, model-gated early DSP hook and pacman boot checks. It contains no vendor-signed DSP firmware or device-specific Wi-Fi calibration. The local stock-machine candidate supplies those through `asus-zenbook-a16-firmware`, built from a checksum-pinned official ASUS download; no previous Linux installation or unlocked Windows partition is required. That OEM firmware package remains a local hardware-test candidate until its changed firmware is validated and redistribution terms are resolved.

The package requires `omarchy-a16-dsp-abi=1` and shared kernel headers. Future `linux-omarchy` versions can retain the audited capability without a version pin; an incompatible kernel update is refused by pacman's dependency checks. The per-release marker is checked again when building the initramfs. Automatic upstream synchronization is disabled because those interfaces require coordinated review.

Build with the normal Omarchy package tooling, after building the kernel:

```bash
OMARCHY_KEEP_BUILD_WORKSPACE=1 ./bin/build --arch aarch64 --package omarchy-a16-support
```

The deterministic support archive is generated by `packaging/omarchy-a16-support/prepare-package.py` in the board-support repository using its compiled public topology. Hardware setup links the package-owned configuration so future support updates affect the next initramfs build. Existing Limine hooks rebuild UKIs after kernel, firmware and initcpio updates.

The WirePlumber keep-awake policy is stored under `/usr/share/omarchy-a16` and linked into `/etc/wireplumber/wireplumber.conf.d` only by A16 hardware setup. Installing the support package on another Snapdragon board does not activate this policy.

The pre-transaction check refuses selected boot-related upgrades when the activated A16 profile has no mounted EFI system partition at `/boot`. The post-transaction check compares the UKI's kernel release, kernel bytes and A16 device tree with the installed package, and checks its initramfs and matching headers. This detects a stale image even when Limine reports success after skipping an unsuccessful build. The check does not prove that the hardware will boot; resolve reported failures before rebooting.

Omarchy's normal `omarchy-update` snapshot and Limine/Snapper integration remain the recovery path. A DSP-disabled fallback is a second profile of the same kernel. It does not preserve a previous kernel's module tree. Kernel updates must also be tested with a pre-update snapshot and an actual restore before upgrade recovery can be declared validated.
